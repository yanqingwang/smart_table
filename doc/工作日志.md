## 2026-08-08 — 本地启动优化（去除 Redis 依赖、pandas 替换为 polars）

### 背景

- 仓库已从 `https://github.com/yanqingwang/smart_table.git` 同步到本地 `/home/wang/wk/code/smart_table`，版本 **v1.6.3**。
- 环境：Python **3.14.6**（系统 `/usr/bin/python`）、Node/npm 可用、无 Docker、pnpm 通过 npm 安装。
- 目标：
  1. 在不使用 Docker 的前提下，本地最简启动前后端；
  2. 去除 Redis 硬依赖；
  3. 用 **polars** 替代 **pandas** 提升导入导出效率；
  4. 依赖尽量升级到最新兼容版本。

### 变更内容

1. **缓存后端可配置（去除 Redis 硬依赖）**
   - `smarttable-backend/app/config.py`：`CACHE_TYPE` 改为读取环境变量（默认 `SimpleCache`），`CACHE_DEFAULT_TIMEOUT` 支持环境变量覆盖。
   - `smarttable-backend/app/extensions.py`：仅在 `CACHE_TYPE == 'RedisCache'` 时才连接 Redis；否则 `redis_client = None`，启动不再因 Redis 未启动而报错。
   - 本地 `.env` 设置 `CACHE_TYPE=SimpleCache`。

2. **pandas → polars**
   - 新增 `smarttable-backend/requirements-local.txt`：移除 `pandas`、`psycopg2-binary`（本地用 SQLite，无需 PostgreSQL 驱动），导入导出改用 `polars`。
   - `app/services/import_export_service.py` 与 `app/routes/import_export.py`：Excel/CSV 导入导出、文件分析（analyze）全部改用 `polars`（读用 `fastexcel`，写用 `xlsxwriter`），并保留编码回退（utf-8 / gbk）。
   - 独立的验证脚本已确认 CSV/Excel 导入、导出、文件分析均通过（输出 `ALL POLARS CHECKS PASSED`）。

3. **登录验证码可开关**
   - `config.py` 增加 `LOGIN_CAPTCHA_ENABLED`（默认 `true`，与上游行为一致）。
   - `app/routes/auth.py` 的注册 / 登录 / 找回密码三处验证码校验均包在该开关内。
   - 本地 `.env` 设置 `LOGIN_CAPTCHA_ENABLED=false`，便于本地免验证码登录。

4. **缺陷修复**
   - `app/services/email_sender_service.py`：将拼写错误的 `stplib.SMTP` 修正为 `smtplib.SMTP`（该文件已 `import smtplib`）。

5. **依赖版本**
   - `marshmallow` 固定 `==3.26.1`、`marshmallow-sqlalchemy==0.29.0`（4.x 移除了 `description` 参数，会导致应用启动失败）。
   - `Pillow` 升级到 `12.3.0`（提供 Python 3.14 的预编译 wheel）。
   - `requirements-local.txt` 其余依赖取兼容的最新版本。

## 2026-08-08（补充）— 修复后端根路径 `GET /` 返回 404

### 问题

本地 `python run.py` 启动后，访问 `http://localhost:5000/` 出现 `GET / 404`，容易误以为启动失败。
原因：后端是纯 API 服务，仅提供 `/api/*` 接口，UI 实际由 Vite 开发服务器（`http://localhost:3000`）提供，根路径 `/` 之前没有路由。

### 修复

- `smarttable-backend/app/__init__.py`：新增 `register_root_route(app)`，在**开发/非打包模式**下将 `GET /` 重定向到前端开发服务器（默认 `http://localhost:3000`，可用环境变量 `FRONTEND_URL` 覆盖）。
- 打包（PyInstaller）模式下不注册此路由，根路径仍由静态文件托管处理。
- 验证：`GET /` → `302` 跳转至 `http://localhost:3000`；`GET /api/health` → `200`。

> 提示：正确访问地址是 `http://localhost:3000`（前端），后端 API 基址为 `http://localhost:5000/api`。
